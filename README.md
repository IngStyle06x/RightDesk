# RightDesk

## 1. Предмет задания
Демонстрационная веб-система приёма обращений граждан в МВД с автоматическим определением подразделения и срочности обращения. Система тестовая, все данные вымышленные.

## 2. Пользователи
- **Гражданин:** регистрируется, отправляет обращения, видит их статусы и ответы.
- **Сотрудник МВД:** закреплён за одним подразделением, видит только его обращения, принимает, передаёт в другое подразделение, отвечает, закрывает.

## 3. Как работает
1. Гражданин отправляет обращение.
2. Модуль ИИ определяет подразделение, срочность и уверенность.
3. Обращение попадает в список подразделения.
4. Если уверенность ниже 60%, обращение уходит в «Канцелярию» на ручное распределение.
5. Сотрудник обрабатывает обращение, гражданин видит ответ.

**Подразделения (7):** полиция, ГИБДД, миграция и документы, киберполиция, экономическая безопасность и коррупция, жалобы на сотрудников, прочее.

**Срочные:** угроза жизни, насилие, пропавший человек, преступление в процессе. Они стоят первыми в списке и выделены цветом.

## 4. Требования к модулю ИИ
- Обучение на собственном наборе обращений (не менее 200 на подразделение, не менее 300 срочных).
- Сравнение двух моделей (TF-IDF + логистическая регрессия и LSTM), подключается лучшая.
- Верно определённых подразделений не менее 85%, срочных обращений находится не менее 90%.

## 5. Тестовые данные
База имитирует МВД: не менее 20 сотрудников, 100 граждан, 1000 обращений. Заполняется одной командой. Нужны готовые тестовые аккаунты гражданина и сотрудников.

## 6. Роли в команде

**Участник 1. ИИ и данные**
- собрать и разметить набор обращений;
- обучить и сравнить две модели;
- написать функцию `predict(text)`, которая возвращает подразделение, срочность и уверенность;
- подготовить отчёт о качестве.

**Участник 2. Back-end**
- спроектировать базу данных и скрипт её заполнения;
- сделать вход, регистрацию и права доступа;
- сделать запросы по обращениям (отправить, список, принять, передать, ответить, закрыть);
- подключить `predict` к отправке обращения.

**Участник 3. Front-end и тестирование**
- сделать страницы: вход, кабинет гражданина, кабинет сотрудника, сводка;
- подключить их к серверу;
- проверить систему по критериям приёмки;
- написать README и подготовить презентацию.

**Как работать вместе:** в первую неделю договориться о формате ответа `predict` и о списке запросов сервера. Пока модель не готова, Участник 2 использует временную заглушку. Код хранится в одном репозитории на GitHub, у каждого своя ветка.

## 7. Приёмка
1. Гражданин регистрируется, отправляет обращение и видит ответ.
2. Сотрудник видит только обращения своего подразделения и выполняет все действия с ними.
3. Срочные обращения выделены и стоят первыми.
4. Сомнительные обращения попадают в «Канцелярию».
5. Показатели модели соответствуют разделу 4.
6. Систему можно запустить по README.

## 8. Не входит в задание
Подключение к реальным системам МВД, мобильное приложение, уведомления, реальные персональные данные.
